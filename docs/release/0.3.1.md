## What changed

The only change is in dependencies and tests. The mapprojax requirement widens to
`mapprojax[astropy]>=0.5.0,<0.6`, which makes ZEA, STG and ARC inputs and
outputs reachable through `from_astropy`. A new `tests/test_zenithal.py` (14
tests) covers them, and it also checks that AZP and ZPN are still refused.
No reprojax source line changed apart from docstrings.

## The gate (G4), on the exact uploaded bytes

The gate used the files downloaded from artifact `14600790814`, and both matched
`SHA256SUMS`. Each stack installed the wheel into a fresh venv together with
`pytest` and `reproject==0.21.0`, using `ci/minimum.txt` or `ci/latest.txt` as
constraints on the CPU stacks. Every run had `PYTHONPATH` unset, and
`reprojax.__file__` resolved to that venv's `site-packages`. The tests ran **one
module per process**, as in the 0.3.0 gate, because one process over the whole
suite runs out of memory on this host. The counts below are sums of those
